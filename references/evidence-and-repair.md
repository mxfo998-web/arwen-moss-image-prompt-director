# 证据、反馈与修正

## 知识来源分层

1. 官方接口规范：约束格式、字段、尺寸和流程。
2. 官方建议/论文实验：注明题材、数据集和比较条件，不将特定测试扩大为所有任务。
3. 摄影/设计原则：是视觉选择方法，不是 MOSS 保证执行的参数。
4. 社区作者观察：保留来源和条件，作为候选技巧。
5. 本地出图复测：记录条件、多个种子和失败例，才能形成有边界的经验。

新事实记录来源、核查日期、模型和工作流版本。没有实测就标“未出图验证”。用户的明确创作偏好只在用户授权保存时更新 Skill，不将一次场景选择推广成永久风格。

## 诊断顺序

先确认实际输入提示词、模型版本、精度、采样参数、自动扩写与额外 LoRA，再定位错误。避免同时改提示词、模型和采样器后把变化归因给某一句话。

| 现象 | 优先检查 | 可能的局部修正 |
| --- | --- | --- |
| 错字、漏字、换行错 | 原文与实际输入、文字量、换行、框与分辨率 | 逐字指定、明确换行、增加文字区域、减少背景干扰；不暗删文案 |
| 位置漂移 | 草稿/最终坐标是否混用、画布是否一致、语言方位是否冲突 | 还原草稿、修正框和描述、重新编译 |
| 多人属性混淆 | 数量、命名、属性归属、遮挡与相似描述 | 每人独立描述并明确站位/关系，必要时用 Layout |
| 风格偏离 | 混杂媒介、参考用途、过多风格词、额外 LoRA | 保留一套主媒介，写具体笔触/材质/光照，修改最相关部分 |
| 灯光或透视矛盾 | 机位、光源、人物朝向、接触与阴影 | 统一视点与主光，明确焦点，纠正物理关系 |
| 画面不够电影化 | 叙事重点、空间、景别与光色是否具体 | 读取 cinematic-language.md，围绕画面目的选择方法 |
| SFT 平滑背景有竖向色带 | 与 Base/其他设置的对照、后处理/量化 | 将其作为模型/工作流问题核查，不承诺加负面词即可消除 |

这些是诊断启发，不是未经验证的修复保证。

## 对照记录

记录：原始需求、提示词/草稿、实际输入、模型与 LoRA、精度、分辨率、steps/CFG/shift/SLG、采样器/调度器、seed、自动扩写状态、结果路径、问题和唯一改变项。

先用同设置多个种子比较旧/新写法，再观察是否迁移到其他场景。保留失败例与用户评价，避免只收录最好看的样张。

观察四项：需求与文字保留、布局/关系执行、可读性与视觉质量、与用户目标的匹配。OCR 可辅助核字，人工复核字形、位置和整体设计。

结构脚本校验与实际图像验证分开报告。当前随包示例只有结构/坐标校验，没有 MOSS 图片结果。
